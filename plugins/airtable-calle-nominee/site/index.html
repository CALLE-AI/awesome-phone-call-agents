Employment verification that refuses the number on the form.

Every mortgage needs it. When the payroll database has no record — which it does for most small employers, and for every country without one — somebody picks up a phone. Nominee makes those calls, asks only what consent covers, and writes a typed answer back into your table.

Three steps, and none of them is a terminal.

Nominee runs on the operator’s own machine and opens in their browser. The queue stays in the Airtable base they already use.

1

Open it

Double-click Nominee.command on macOS or run.bat on Windows. The panel opens in your browser.

With no credentials it starts on sample data, so the first thing you see is the product working.

2

Connect your base

Paste an Airtable token, your base, a CALL-E key and your organisation’s name. Stored in a local file only you can read.

Your answer columns become the extraction schema — a single select’s choices are the allowed answers, its description is the instruction.

3

Preview, then run

You see every row in scope, every row being skipped and why, how many the view’s filter is hiding, the estimated spend, and the verbatim script that will be spoken.

Results land back in your base as each call finishes.

Two boundaries, enforced by construction.

Not policy someone can forget — types that cannot be built the wrong way, with tests that fail if that ever stops being true.

Consent

A filled-down cell is not consent

Ticking one checkbox and dragging it down a column is the most ordinary gesture in a spreadsheet — and it would authorise every row it touched.

So consent is a hash of the row’s own content. A token copied from another row was derived from a different number, and is refused. Editing the questions revokes every consent gathered under the old wording.

sha256(request | phone | relationship
       | spec_version | receipt_id)
Provenance

The number on the application is never dialled

Fraudulent applications supply working numbers — with staffed call centres and directory listings. It is the one field an applicant fully controls, and the manual process calls it anyway.

Nominee structurally cannot. The dialer accepts only an independently sourced number; the applicant-supplied one is a different type with no conversion path.

No independent source? The request fails closed as employer unverifiable — which is itself a recognised fraud red flag, not an error.

Nothing verified without contact
CALL-E can report a task complete when setup fails before dialling. Nothing reaches a positive result without extracted evidence that a person was actually reached.
A refusal is a complete answer
An employer declining to confirm has not failed. That outcome is terminal and never retried — redialling them is harassment, not persistence.
Fails closed, always
Low confidence, a positive claim with no supporting evidence, or any internal contradiction all route to a human. No rule can promote a result.
Hash-chained audit
Editing a record, deleting one, or reordering breaks the chain and names where. Written and flushed to disk before the call it authorises can ring.
Nothing is reachable from outside
The panel binds loopback only and needs a one-off token. Its run endpoint accepts a view name — never a destination — so no request can introduce a phone number.

What it is not.

Saying so plainly is part of the design, not a disclaimer.

Not a collections tool Not a credit decision engine Not a background check Not a salary lookup Not a replacement for a payroll database
