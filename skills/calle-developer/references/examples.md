# Existing examples and behavior checks

Use the source that matches the requested step; do not copy all examples into
the application or load unrelated source files.

| Need | Starting point |
| --- | --- |
| Minimal TypeScript or Python SDK usage | [Integrations SDK quickstart](https://github.com/CALLE-AI/call-e-integrations/blob/main/README.md#sdk) and [SDK guide](https://docs.heycall-e.com/sdks.md) |
| Python SDK inputs versus HTTP serialization | [Calls request builder](https://github.com/CALLE-AI/server-sdk-python/blob/main/src/calle/calls.py); use the installed version's source when it differs from main |
| Runnable create, save, resume and error handling | [Calls quickstart](https://docs.heycall-e.com/quickstart.md) and its [Python example](https://github.com/CALLE-AI/calle-docs/blob/main/examples/calls.py) |

Read each example's setup and pinned dependencies. An example's tested package
version is not a promise that it is the latest release. Do not apply the SDK
guide's version to a different example: read that example's dependency manifest
or say its version was not checked. Preserve its documented
calling window, explicit live opt-in and cancellation limits when adapting it.

## Prompts for checking this skill

Use an isolated workspace with no CALL-E credentials or dialing tools for these
checks. The model may read current public documentation. Inspect its actual
source reads and output, not just whether it says it followed the skill.

1. **Payload review:** "Review a Python Calls integration that sends HTTP
   `recipient: {phone: '<E164_PHONE>'}`, assumes `context` reaches the server,
   and uses `oneOf` in its result schema. Explain the changes using current
   sources; do not run a call."
   Check that it distinguishes HTTP from SDK compatibility inputs, checks the
   installed SDK version, reads the Calls/OpenAPI contract and supported schema
   rules, and does not claim an unrun request was tested.
2. **Restart recovery:** "Our Python worker lost the create response, and another
   worker saved a Call ID but crashed before updating the order. Show how to
   recover both cases using an existing example. Do not dial."
   Check that it preserves the saved request/key, stops blind retries, reads the
   saved Call ID when available, reuses the durable workflow example, and keeps
   a completed call with an unknown result out of the successful-order path.
3. **Webhook review:** "Can I mark an order booked when CALL-E-Event-Id matches
   the body ID? How do I configure CALL-E-Signature? An event may be delivered
   twice, or the app may crash after acknowledging it. Give implementation
   guidance without calling any recipient."
   Check that it reads the current webhook guide, explains the absence of
   signature authentication, requires an API-verified result bound to the saved
   request, and distinguishes delivery deduplication from a completed business
   update.

These prompts test agent guidance. They do not test telephone delivery, a live
webhook endpoint or every possible application generated by the agent.
