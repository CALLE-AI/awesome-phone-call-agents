# Safety contract

This skill places **real phone calls** to businesses on a person's behalf. Treat
every call as an irreversible side effect and follow these rules.

## Consent and intent

- Only place a call when the user clearly intends one. Setup, testing, and
  "what would this do?" questions must use the dry-run path and place no call.
- Always run the `place-call.mjs` dry-run first and show the user the masked
  recipient and the exact task the agent will follow. Place the real call only
  after the user consents to *that* plan.
- Scheduled or repeated calls need the user's up-front approval for the whole
  series; do not silently place calls the user did not ask for.

## Disclosure

- Every task generated by `build-task.mjs` opens with a fixed instruction to
  **disclose, at the start of the call, that the agent is an AI assistant calling
  on the user's behalf** — not the account holder in person. This disclosure is
  not user-editable; do not remove or weaken it.

## Phone numbers and locale

- Require recipient numbers in **E.164** (`+` and country code, e.g.
  `+14155550123`). `place-call.mjs` rejects anything else — do not "fix" it.
- Never guess or infer country code, region, or language. Ask the user.
- Mask phone numbers in anything shown back to the user (the scripts do this).

## Identity and PII

- The agent must never invent account numbers, PINs, card numbers, SSNs, dates
  of birth, or other personal details. If a rep asks for something the user did
  not provide, the agent says it does not have it on hand and offers to follow up.
- Only share an `accountRef` the user explicitly provided and is comfortable
  sharing. Do not read back full card or account numbers.

## Decision authority

- Default to **capture, don't commit**: the agent negotiates and records the exact
  best offer, then tells the rep the user will confirm shortly.
- The agent may accept/commit on the user's behalf only when the user explicitly
  chose autonomous mode and set a concrete limit (e.g. `autoAcceptBelow`).
- Never cancel, purchase, or agree to a binding change outside the stated goal.

## Honest reporting

- Report only what CALL-E actually returned. Do not claim a call was placed, a
  deal was struck, or a booking was made unless the structured result confirms it.
- Surface `completion_confidence` and, when the outcome is `partial` or
  `failed`, say so plainly and offer at most one escalated follow-up.

## Credentials

- `CALLE_API_KEY` stays in the environment. Never print it, log it, or include it
  in user-facing summaries or the dry-run output.

## Out of scope

- No mass/robocall outreach, sales spam, or calls to recipients who have not
  consented to contact.
- No medical, legal, financial, or emergency advice during a call — collect
  logistics or route to a human instead.
- No impersonation of the account holder beyond relaying details the user gave.
