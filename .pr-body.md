## What this adds

`apps/python/blood-bank-dispatch/` — a runnable Python app that files one blood-stock request and fans out one CALL-E call per blood bank **in parallel**, asking a fixed set of stock questions (units available, screening/cross-match status, release policy, cost per unit, transport time, contact person, alternatives). Results are extracted into a strict JSON schema, persisted in Postgres alongside the raw CALL-E response and transcript, and rendered as a live card UI with a ranked shortlist for a human to act on.

A serial 20-minute manual calling loop becomes a parallel 90-second one. The agent only gathers and reports: it never reserves, never dispatches, and never makes a clinical decision.

## CALL-E usage

- Python SDK (`calle-ai`), `client.calls.create` + `wait_for_result`, called at runtime via `asyncio.to_thread`
- Persisted idempotency keys (`run:{id}:bank:{key}:v1` sent as the `Idempotency-Key` header); network retries replay instead of double-dialing (verified live)
- `result_schema` / `recipient_result_schema` with `unknown` enum members, per the API's own guidance — hedged answers are kept as real information
- Transcripts (`recipients[n].attempts[m].transcript_turns`) stored as raw evidence beside every parsed column
- Unsigned 0.7.0 webhook deliveries handled per current guidance (`CALL-E-Event-Id` dedup); the polling UI does not require webhooks

## Safety

- **No calls by default**: `DRY_RUN=1` runs the entire pipeline — fan-out, extraction, persistence, UI — against four simulated personas (stock / alternatives / callback / no-answer) with no credentials and no spend. Live calls are an explicit opt-in (`DRY_RUN=0`).
- Decision-support boundary stated in the task prompt, UI, and README: never reserve, never promise, never diagnose.
- E.164 validated on write; samples use reserved fictional numbers (`+1555010xxxx`); server-side rate limiting and a server-side per-run target cap; no patient names; API keys server side only.

## Testing

```bash
cd apps/python/blood-bank-dispatch
python3 -m venv venv && venv/bin/pip install -r requirements.txt
python3 migrate.py && python3 seed.py
venv/bin/python -m uvicorn app.main:app --port 8000
```

Runs end to end in dry-run mode with only a Postgres URL configured. `scripts/run_status.py` summarizes the latest run; `scripts/recover_stuck_call.py` re-drives a stuck row via idempotent replay.
