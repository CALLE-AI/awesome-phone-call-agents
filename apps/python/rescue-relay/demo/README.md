# Reproducing the actual-UI videos

The complete release contains two caption-led H.264 MP4s in `static/media/`. The shorter cut is for the Devpost submission; the longer one adds contact creation, saved conversations, sharing and report history. Both go from a fresh workspace through safe closure.

```bash
python -m pip install -r requirements-dev.txt
python -m playwright install chromium
# Install ffmpeg and ffprobe using your OS package manager.
python scripts/record_tutorial.py --mode both
python scripts/build_walkthrough_data.py
```

Use `--quick` for the same visible journey and assertions without deliberate reading pauses or video rendering. Use `--mode demo` or `--mode full` to render one cut. Each run owns a temporary database and forces fictional calling with blank provider/model credentials; it never opens the user's saved database.

`release_journey.py` is the shared UI journey. It clicks real buttons, enters real text, uses real confirmation dialogs and receives the actual isolated API results. It does not pre-render scenes, inject a completed app state or replace backend responses. Regression tests elsewhere may use fixtures; the published video journey does not.

Capture viewport: 1600 × 820. FFmpeg adds an 80-pixel caption band below the app, producing 1600 × 900 (16:9) at 30 fps. Controls are never covered by captions. No music or voiceover is included. The demo asserts its rendered duration is below 180 seconds. Captions, chapter timestamps, SHA-256 and checks are saved alongside the footage.

Output paths:
- Rendered media: `static/media/rescue-relay-demo.*` and `rescue-relay-tutorial.*`.
- Viewport screenshots and check results: `artifacts/release/demo/` and `artifacts/release/full/`.
- Raw temporary capture: `demo/raw/`, excluded from distribution and source control.
- Player chapter data and posters: generated by `build_walkthrough_data.py`.

The default browser path visits localhost normally. The optional `BROWSER_HTTP_BRIDGE=1` uses the real HTML/CSS/JS inline and forwards the real isolated HTTP API for restricted browser environments. It does not prove browser enforcement of production CSP/origins or ordinary-origin storage behaviour. The release recording used this bridge because direct browser navigation was administratively blocked.

After any future UI edit, rerun the journey and regenerate the media. Do not change only the footage or the demo badge to make it look like a provider-backed live call. Main UI remains identical between demo and live except for truthful mode, consent, status and demo-only controls.
