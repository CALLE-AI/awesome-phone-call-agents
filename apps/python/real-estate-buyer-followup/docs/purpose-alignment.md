## 已完成的演示路径

1. **客户工作台**：虚构张女士 C001，浦东三房、预算500万、3个月内；历史沟通按日期展示，两套已看房源分别显示。内部保留原始稳定ID，界面额外展示C001/P001/P002。
2. **Agent 分析与规划**：展示预算事实、空间变化、地铁范围未知、分房源反馈缺口与价格取舍；每项可看到来源原文、判断等级和建议动作。三个规划目标、分房源问题、理由、优先级、跳过项与约束可审核编辑。判断等级不等于校准概率。
3. **通话执行**：批准计划后才出现执行按钮；Mock 显示虚构转写和状态，Live 需另行启用、授权和确认。处理只生成持久化更新建议，此时不改客户和带看数据。
4. **结果与更新**：总结、结构化输出、旧值/新值、证据、待确认项和后续行动集中显示。点击「确认并更新 Mock CRM」后才实际回填；高影响字段继续单项审核。返回第一页可见反馈与客户状态。

普通案例记录继续看房意愿，保持预算500万。交通只记录定性变化，原10分钟字段保留为历史约束，当前可接受范围仍未知。该缺口继续显示为待跟进，不伪装成已明确。

高意向案例关联B滨江公馆：希望价格能谈到500万左右、本周复看并让经纪人联系。产生有依据的高优先级建议，不改B报价、不自动加预算、不预约。

## 当前要求：不写CRM与经纪人知识库

Web与默认工作流均使用只预览模式。即使程序传入confirm_writeback也不写客户、带看、需求变更历史或提醒表；适配器还会拒绝直接写入。客户资料每次从初始fixture读取，旧数据库不被清空或覆盖。任务、转写和建议独立保存；结果显示“拟更新，未写入”，去掉写库和单项确认入口。刷新仍保持未回填。存储回填原型仅供显式内部测试，不是当前Demo行为。

新增经纪人可编辑的[上海购房政策知识库](../src/real_estate_buyer_followup/knowledge/shanghai-homebuying.md)：5项官方来源资料，附日期、适用前提与参考级别。Agent按任务自动选择条目和段落，程序按编号取原文，避免让模型逐字复述政策导致引用不匹配。只将选中条目交给规划及电话任务；不得把一般政策当成张女士个人资格。页面展示原文、来源、选择理由及仍需核实的条件。本地库不是实时联网搜索。

知识筛选现为独立豆包步骤：先理解客户，再按经纪人目标筛选政策，最后生成通话计划。实际针对积分/贷款问题选择了对应条目，避免整体分析遗漏显式问题。39项测试通过。
