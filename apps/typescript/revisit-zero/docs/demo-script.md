# RevisitZero demo script and storyboard

**Target duration:** 2:45 (acceptable recording window: 2:40–2:50)
**Mode:** Fake / no-call demo, fictional data only
**Recording format:** 16:9, 1440p preferred, cursor visible, notifications disabled

## 0:00–0:15 — The promise

**On screen:** Product title, fake/no-call banner and three case tabs.

**Narration:** “A meter visit can fail for a simple access problem—or for a reason automation must not touch. RevisitZero turns one failed visit into one controlled call and one trustworthy rebook decision.”

**Operator action:** Point briefly to the banner: fictional data, no external side effects.

## 0:15–0:35 — The narrow boundary

**On screen:** Case 1 selected; sweep across the three columns and the scope strip.

**Narration:** “The workbench keeps the source failure, call control and decision together. It never books a technician, updates another system or notifies anyone. It stops at a human-approved local export packet.”

**Operator action:** Highlight “No booking,” “No CRM update,” and “No automatic retry.”

## 0:35–1:08 — Deterministic eligibility and exact approval

**On screen:** MTR-2026-0042, the smart-meter replacement blocked by a locked side gate and unsecured dog.

**Narration:** “The first case is eligible because the failure is access-only, the service contact is authorised, the fictional test number is valid, and the contact window is open. Before contact, the operator previews one exact conversation: the masked recipient, objective, six allowed questions, offered windows, and the information CALL-E must never collect.”

**Operator action:** Scroll within view only if needed. Point to “Never collect” and “One attempt; no automatic retry.” Click **Approve this exact call**.

**Narration:** “Approval is content-bound. Change the case, recipient, questions, objective or windows, and the receipt is invalid.”

## 1:08–1:32 — Run the safe fake transport

**On screen:** Approved receipt and enabled fake-transport button.

**Narration:** “For judging, CALL-E is replaced by the included fake transport, so nobody is called. A participant-authorised live check completed one provider call and demonstrated the fail-closed boundary: a contradictory result was quarantined, export was blocked and no duplicate call occurred. The corrected provider contract now uses one authoritative outcome and derives opt-out locally.”

**Operator action:** Click **Run fake CALL-E transport** once. Do not double-click.

**Narration:** “There is never an automatic redial. An ambiguous provider outcome is preserved for reconciliation.”

## 1:32–1:58 — Validate, decide, and stop

**On screen:** Validated structured result and `READY_FOR_REBOOK_REVIEW`.

**Narration:** “The closed provider result uses supported simple types and exact offered-window options plus a NONE sentinel, which normalizes locally to no selection. Here every blocker is resolved, Thursday afternoon is selected, and strict schema and contradiction checks pass. No gate code or free-form personal narrative was collected.”

**Operator action:** Point to the validated badge, disposition, masked recipient, call ID/idempotency reference and pending export approval.

**Narration:** “Local deterministic rules recommend ready for rebook review. That is a recommendation—not a booking.”

## 1:58–2:13 — Separate human export approval

**On screen:** Local export packet card.

**Narration:** “A second human checkpoint controls the only side effect: downloading a fictional JSON packet to this device.”

**Operator action:** Click **Approve local export**, then show **Download approved JSON**. For a clean recording, do not open the system download shelf; the click can be omitted if it would interrupt the frame.

## 2:13–2:30 — Manual-review refusal

**On screen:** Select MTR-2026-0043.

**Narration:** “The second case fails differently. A body corporate controls the shared meter room. RevisitZero will not switch recipients or contact that external party. It routes the case to manual review without a call.”

**Operator action:** Point to `MANUAL_REVIEW_REQUIRED`, “Call unavailable,” and the unresolved access authority.

## 2:30–2:42 — Safety refusal

**On screen:** Select MTR-2026-0044.

**Narration:** “The third case records a suspected electrical or site defect. The deterministic safety gate blocks automation before approval or contact.”

**Operator action:** Point to `AUTOMATION_BLOCKED` and the untouched call stage.

## 2:42–2:47 — Close

**On screen:** Hold on the full blocked-case workbench, then return to the title area if the move is smooth.

**Narration:** “RevisitZero is useful because it knows when one controlled call is enough—and when no call is the right answer.”

## Recording checklist

- Keep the final cut between 2:40 and 2:50; rehearse once at 2:45 before recording.
- Show the fake/no-call banner in the opening frame and never imply a real call succeeded.
- Use only the three included fictional cases.
- Keep the browser zoom between 90% and 100% so all three columns remain legible.
- Avoid fast cursor movement, text selection and unnecessary scrolling.
- Pause for roughly one second after each click so state changes are visible.
- Do not show environment files, credentials, real phone numbers, local usernames or unrelated tabs.
- Add captions for status names and preserve exact enum spelling.
- If the live adapter is mentioned, describe readiness and controls—not a completed real call.
- End with the safety boundary, not an unsupported impact claim.
