# Video script — E-mploye for CALL-E

Target length: 2:00–2:40. Record the public URL in a desktop browser at 100% zoom. Keep the browser viewport wide enough to show the dashboard without an internal scroll. Use the first prepared scenario for the complete story; the other two workflows are supporting proof of the reusable product.

## Before recording

- Open <https://e-mploye-for-calle.vercel.app> in a clean browser tab.
- Confirm the header says **CALL-E SANDBOX** and **1 virtual employee**.
- Click **Reset demo** so the appointment scenario is ready.
- Record the browser content only if the browser chrome or desktop notifications distract from the product.
- Do not enter a real API key or personal phone number in the public demo.

## Shot list and narration

| Time | Action | On-screen message / narration |
| --- | --- | --- |
| 0:00–0:15 | Hold on the dashboard header. | “E-mploye is one virtual employee for routine business calls. It previews every task, keeps a manager in the loop, and returns evidence before anything changes.” |
| 0:15–0:30 | Move across the three workflow cards. | “The same employee adapts to service appointments, sales follow-up, and team operations.” |
| 0:30–0:45 | Select the prepared **Appointment reschedule** scenario and click **Start scenario →**. | “I will demonstrate a customer asking for another appointment time.” |
| 0:45–1:00 | Click **Preview task** and pause on the preview. | “The exact instruction, masked destination, locale, and safety checks are visible before a call can run.” |
| 1:00–1:15 | Click **Request approval**, then **Authorize call →**. | “Previewing creates no call. A separate manager authorization is required before the sandbox provider runs.” |
| 1:15–1:35 | Show the **CALL-E EXECUTION** trace while the fake call completes. | “The trace makes authorization, provider execution, status refresh, and the returned result observable.” |
| 1:35–1:55 | Show the structured result, confidence, transcript, and evidence. | “The answer is structured and reviewable. E-mploye does not silently update the appointment.” |
| 1:55–2:10 | Click **Approve & apply appointment**. | “Only after human review does the approved reschedule update the scheduled context.” |
| 2:10–2:25 | Return to the dashboard and point to the three prepared scenarios. | “The same approval, evidence, persistence, and safety engine is reused across all three business workflows.” |
| 2:25–2:40 | Hold on the footer and sandbox badge. | “The public demo is deterministic and uses no phone credits. The repository also includes a server-only live CALL-E adapter through the official SDK, verified with mocked HTTP 201 and 200 contract responses.” |

## If the video needs to be shorter

Keep the header, three workflow cards, preview, approval boundary, execution trace, result evidence, and human-approved apply. Skip the second scenario interaction. The three cards already communicate the multi-rubro scope without adding a second long run.

## Recording notes

- Audio is optional if the English captions and visible actions are clear; a short voiceover plus captions is stronger.
- Keep the cursor visible when clicking **Preview task**, **Request approval**, **Authorize call**, and **Approve & apply appointment**.
- Pause for one or two seconds after each state change so reviewers can read the trace and evidence.
- If the fake run is still queued, click **Refresh** once; do not reload the page mid-flow.
- End with the public URL visible and the demo reset if the submission requires a clean final frame.
